### 内部画面の確認

架空のMELSEC CSV・KEYENCE MNMを使用し、Edgeで内部画面・Worker・解析処理を動かした。Windowsとのファイル／コピー連携部分は確認用の代替処理を使用したため、下表だけではWindowsのファイル選択やクリップボードの動作確認にはならない。

25組の操作確認は、修正後の再確認を含めすべて通過した。これらはリポジトリの全体テストとは別の確認。

| 対象 | 確認できた内容 |
| --- | --- |
| 幅・倍率 | 初回幅合わせ、比較の片側切替・サイズ変更後の幅合わせ、検索・コメント切替時の手動倍率保持 |
| 移動 | 通常／直接比較の末尾回路で上部に空白が残らないこと、前後の差分で先頭・末尾に停止すること |
| 検索・STEP | 通常／直接比較／片側表示のGLP移動、FB端子・インラインST本文検索、STFORの対応STEP移動、ポインターだけのSTEP表示 |
| 差分 | 同じ前半を持つ回路の挿入、未変更命令の色維持、追加・削除、命令名／引数だけの文字強調、ANBからORBへの接続変更 |
| 配線 | 注記だけを変えて行間が広がっても配線を差分にしないこと |
| 色 | ライト・ダークそれぞれで標準／高コントラスト／目にやさしい／CUD／ブルーの5配色、インデックス色・差分背景・選択枠 |
| 図・注記 | FB/FUN端子名と接続先、STのコメント帯・本文、MCネスト／未閉鎖の破線、REPEAT・CASEELSE・多数ELSIFを含む範囲表示 |
| 長い回路 | 折り返しと回路単位の横スクロール、短い回路の幅維持 |
| KEYENCE | パルス反転接点、KEEPのSET／RES、MPS／MRD／MPPの最終枝、タイマ、同名ファイルのフォルダー別コメント切替 |
| コピー内容 | インデックス・全文コメント・複数行ノート、比較左右のコメント分離、ポインター、FB本体と各ピンの内容 |

### 計測

ローカルのKEYENCEデータ72プログラムずつを新しいNode.jsプロセスで1回処理した。同一53組・差分あり19組。入力の内容・パス・プログラム名はこの記録へ含めない。

| 処理 | 計測値 |
| --- | ---: |
| ファイル読込み | 11ms |
| 解析 | 115ms |
| 一覧の同一判定 | 47ms |
| 全プログラムの比較合計 | 218ms |
| 最長の1プログラム比較 | 43ms |
| 観測した最大JSヒープ | 120MiB |

Node.jsはv24.14.1。JSヒープはWindows版プロセス全体のメモリ使用量ではない。内部画面のスクロール操作30回では次の描画フレームまで中央値16.5ms・95パーセンタイル21.8msだった。ヘッドレス描画での参考値であり、実画面の長時間操作の計測は別途必要。

### 確認中に修正した不具合

- 命令のないポインターだけの回路にSTEPが出ない。
- 直接比較の制御範囲・命令詳細から対応STEPへ移動できない。
- FB端子の検索で、端子より先に親FBが一致してしまう。
- CSVを個別指定すると、不要なnull値を含む受信データが検証エラーになる。
