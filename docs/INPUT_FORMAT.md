# 文字コードとコメントCSVの判定

[ビルド・テスト](BUILD.md)

文字コードはBOMを優先します。UTF-8 BOM、UTF-16 LE BOM、UTF-16 BE BOMを認識し、BOMが示す文字コードで厳密にデコードします。BOMなしでは厳密なUTF-8を試し、不正ならCP932（WindowsのShift_JIS）を試します。どちらでもデコードできなければ読込みエラーです。

コメント形式は先頭10個の非空白の物理行で判定します。各行をタブ区切り、次にカンマ区切りで解析し、引用符内の区切り文字と二重引用符のエスケープを扱います。フィールド前後の空白は除きます。ヘッダー自体の改行は対象外です。

- 三菱：先頭フィールドが`デバイス名`、2列以上、`命令`と完全一致するフィールドがない行。
- キーエンス：最初の非空白行がカンマ区切りで、先頭3列が空文字・空文字・`コメント1`。
- 先に見つかった形式を採用します。一致しなければコメント表ではありません。コメント本文の構文検査は形式判定後に行います。

この規則の共通データは[comment-formats.json](../tests/fixtures/comment-formats.json)です。全データは架空で、デコード結果と判定結果を持ちます。TypeScriptテストとC#チェックは同じバイト列と期待値を読みます。規則を変更するときはこの文書・両実装・fixtureを同時に更新します。
